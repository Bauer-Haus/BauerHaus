# Security Policy

## Reporting a vulnerability

Email **bauer@bauerhaus.io**. Please include enough detail to reproduce the
issue — a proof of concept, the affected version, and the macOS version you saw
it on. You will get an acknowledgement within 5 business days.

Please do not open a public GitHub issue for a security report.

We ask for 90 days before public disclosure, and we are happy to credit you in
the release notes for the fix unless you would rather stay anonymous.

## Supported versions

Only the latest published release of each app receives security fixes.

| Product     | Supported                       |
| ----------- | ------------------------------- |
| WindowSmith | Latest release (currently 1.1)  |
| bauerhaus.io| Yes                             |

## Verifying a WindowSmith download

**Automatic updates.** `WindowSmith/appcast.xml` is consumed by Sparkle 2. Every
enclosure carries an EdDSA (`sparkle:edSignature`) signature made with the
private half of the key embedded in the app bundle. Sparkle verifies that
signature before it will install anything, so a tampered appcast or a swapped
DMG is rejected even if the web host is compromised.

The private half of that key is never committed to this repository and is never
exposed to CI; appcast entries are signed locally with Sparkle's `sign_update`
before the feed is pushed. Losing the key means existing installs can no longer
be updated, so it is kept backed up offline.

**Manual downloads.** The DMG offered on the website is not signature-checked by
the browser beyond Gatekeeper. Checksums for every published build are listed in
[`WindowSmith/downloads/SHA256SUMS.txt`](WindowSmith/downloads/SHA256SUMS.txt):

```sh
shasum -a 256 ~/Downloads/WindowSmith-1.1.dmg
```

`.github/workflows/release-integrity.yml` re-checks, on every push and pull
request, that each appcast enclosure points at a file that exists in the repo,
that its `length` matches the real byte count, that its checksum matches
`SHA256SUMS.txt`, and that it is served over HTTPS with a signature attached. A
release that does not line up fails CI instead of reaching the site.

## Scope

In scope: the bauerhaus.io site, the release pipeline in `.github/workflows`,
the Sparkle update feed, and the WindowSmith application itself.

Out of scope: findings that require a jailbroken or already-compromised Mac,
missing security headers that GitHub Pages does not allow us to set, and reports
generated by an automated scanner with no demonstrated impact.
